# 成果呈现 · 事项清单

从 `SKILL.md`「成果呈现」按需打开。只列流程事项，不规定具体 CLI、厂商字段或仓库骨架。

## 选择门（必做）

收束后先问，三选一：

- **A** 仅本地 HTML
- **B** 对外发布
- **C** 先不要

未选 → 停。

---

## A · 仅本地

| # | 事项 | 说明 |
|---|---|---|
| A1 | 文稿收敛 | 用本轮过关要点组织：问题、方法、流程、边界、收获 |
| A2 | 路径确认 | 文件写到哪里由用户定 |
| A3 | 静态页产出 | 可本机打开的 HTML（单页即可） |
| A4 | 本机验收 | 用户打开看过才算；后续改动需用户说 |

---

## B · 对外发布

| # | 事项 | 说明 |
|---|---|---|
| B1 | 发布意图 | 给谁看、是否必须自定义域、是否已有托管 |
| B2 | 对外文稿 | 正式语气；结构完整；少口语与「不是…而是…」 |
| B3 | 静态产物 | 先有可预览内容，再谈上线 |
| B4 | 托管选型 | 跟用户已有栈；没有则给选项让用户选，不擅自开通账号 |
| B5 | 域名与证书 | 仅当用户要自定义域时：解析 → HTTPS → 等待生效 |
| B6 | 部署授权 | 用户明确「部署 / 上线」后再做；验收以用户浏览器为准 |
| B7 | 定稿打磨 | 版式与文案按反馈改；一次一条主线 |

### 文稿结构（可裁剪）

1. 问题 / 为何学这个  
2. 核心流程或主线  
3. 关键抽象 / 名词  
4. 机制要点（按主题裁剪）  
5. 结论与边界  
6. 对照或位置（可选）  
7. 附录与真源链接（不要「版式参考」类元信息）

### 打磨时常见关注点（非强制清单）

- 内容是否在版心宽度内自然换行  
- 章节标题是否过出口语解释  
- 折叠块 / 摘要行是否可读、对齐舒服  

---

## C · 先不要

记录「本轮无成果页」，结束。用户以后可再说 A 或 B 补做。

---

## 与品牌线（可选）

若用户提到既有对外线（例如 Paper Lab、公司子域、参考站）：

- 在 **B1 / B4 / B5** 对齐其命名与观感期望  
- 不把任何单一域名、scope、DNS 写法写成本 skill 的全局默认  
- 细则以用户当场说明 + 其现有项目为准
